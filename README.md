# CAMRA – Context-Aware Mobile RSU Allocation

M.Sc. project, University of Bremen, Communication Networks (ComNets).
CAMRA decides, window by window, **how many and which mobile roadside units (MRSUs: buses and trams carrying a radio unit) should be switched on** in a VANET scenario, so that the quality of service stays above a target while as few MRSUs as possible are active. It is implemented in [Artery](https://github.com/riebl/artery) (OMNeT++ / SUMO / Vanetza) on real Bremen (OpenStreetMap) and Luxembourg (LuST) traffic.

## How it works (short)

* **Sense** – every 10 s each active MRSU reports traffic and radio measurements (delay, coverage, ...) to the segment coordinator (SCM).
* **Decide** – every 30 s the coordinator computes the QoS error `E` (delay and coverage) and compares it with a threshold `e_monitor`. Above it, a sleeping candidate is activated; far below it, an active one is put to sleep.
* **Act** – switch ON / switch OFF commands are sent to the chosen buses or trams. The loop repeats for the whole run.
* **Dynamic threshold** – `e_monitor = clamp(0.25 − 2·σ − rise, 0.10, 0.20)`, with σ the standard deviation of the last 4 errors and `rise` the latest increase; `e_comfortable = ⅔·e_monitor`, `e_sleep = ⅓·e_monitor`. Constants are in `SegmentCoordinationServer.h` (`ENABLE_DYNAMIC_THRESHOLD`, `DYN_*`).
* **Segmentation** – a city is split into segments of about 5–20 km², each with its own coordinator.

## Installation

1. **System packages** (Ubuntu 24.04): `sudo apt install build-essential cmake git python3 python3-pip libboost-all-dev libcrypto++-dev libgeographic-dev libxml2-dev libprotobuf-dev protobuf-compiler ...` (see `env_versions.txt` for the packages present on the evaluation machine)
2. **OMNeT++ 5.6.2** – build from source. On Ubuntu 24.04 set `WITH_OSG=no` and `WITH_OSGEARTH=no` in `configure.user` (otherwise configure fails on missing OpenSceneGraph packages). Use `make -j4` (not `-j$(nproc)`) to avoid freezes.
3. **SUMO** 1.27.1 with `SUMO_HOME` set; `sumo --version` must work from the shell that starts the simulation.
4. **Artery** at the pinned commit, including submodules:
   ```bash
   git clone https://github.com/riebl/artery.git ~/artery
   cd ~/artery && git checkout 77c0938d3519a11d0642d4279e1471e0c196f733 && git submodule update --init --recursive
   ```
5. **Add the CAMRA scenarios and apply the source patch**
   ```bash
   cd /path/to/this/repo
   cp -r scenarios/mrsu_bremen2 scenarios/mrsu_bremen3 scenarios/mrsu_fullcity scenarios/bremen3_hotspot_patch scenarios/mrsu_lust ~/artery/scenarios/
   gunzip -k ~/artery/scenarios/mrsu_fullcity/mrsu_fullcity.net.xml.gz   # the full-city network is stored compressed (the unpacked file is 293 MB)
   cd ~/artery
   git apply --check /path/to/this/repo/patches/artery-src-changes.diff   # dry run
   git apply /path/to/this/repo/patches/artery-src-changes.diff
   ```
   The patch also registers the new scenario folders in `scenarios/CMakeLists.txt`.
6. **Build**
   ```bash
   mkdir -p build && cd build
   cmake -DCMAKE_BUILD_TYPE=Release ..        # options used: WITH_INET=ON WITH_VEINS=ON WITH_ENVMOD=ON WITH_STORYBOARD=ON (others default/OFF)
   cmake --build . -j4
   ```

## Running

```bash
cd ~/artery/scenarios/mrsu_bremen3
~/artery/build/bin/run_mrsu_bremen3 -u Cmdenv -c inet omnetpp.ini --seed-set=1000 --traci.launcher.seed=50000
```

* Results (`scm_history_*.csv`, `communication_summary.csv`, ...) are written to `results/`.
* **Batches with different seeds:** `tools/run_bremen3_batch.sh` (20 runs, seed-set 1000..1019, SUMO seed 50000..50019), `tools/run_fullcity_batch.sh`, `tools/run_lust_batch.sh`. Edit the paths at the top of each script. The CAMRA dynamic-threshold batch used seed-set `999+i` and SUMO seed `49999+i` for run `i` (1..30).
* Strategy modes (CAMRA, Always-Active, Fixed-Single, Static-Periodic) are selected in `SegmentCoordinationServer.h` / `omnetpp.ini`.

## Evaluating results

```bash
python3 analysis/compute_efficiency.py            # one run: Q, R, efficiency, blackouts
python3 analysis/aggregate_runs.py ...            # many runs
python3 analysis/ci_summary.py --name CAMRA "results_batch/run*/scm_history_CAMRA.csv"   # mean, SD, 95 % CI (Student's t)
```

Metrics: quality `Q = 1 − mean(QoS error)` (cold-start window excluded); a *blackout* is a window with no active MRSU and 0 % coverage and costs 0.15 of `Q`; quality bar 0.75; resource usage `R` = mean(active / reporting candidates); efficiency `Q/R` (only if `Q ≥ 0.75`). Confidence intervals are 95 % CIs of the mean based on Student's t distribution (`--normal` switches to the normal distribution).

## Known pitfalls

* SUMO route files must be sorted by departure time; out-of-order vehicles are dropped silently.
* Single-lane roads cause departure delays and TraCI "vehicle not known" crashes; use at least two lanes.
* The network needs a proper geographic projection (real lon/lat, UTM zone); `projParameter="!"` breaks Vanetza's ASN.1 coordinate constraints.
* `~` is not expanded inside colon-separated `-n` strings of OMNeT++; use `$HOME`.
* If the OMNeT++ IDE is unstable under WSLg, export results with `opp_scavetool`.
* Same seed does not reproduce bit-for-bit after the first MRSU activation (radio layer), so repeated runs are independent draws.

## LuST scenarios

`scenarios/mrsu_lust/` contains two Luxembourg (LuST) variants:

| Variant | SUMO config | Network and routes |
|---|---|---|
| 15 km2 region of interest (default) | `mrsu_lust.sumo.cfg` | `lust_roi15.net.xml`, `lust_roi15_*.rou.xml` |
| 20.25 km2 segment | `mrsu_lust_segment20.sumo.cfg` | `lust_segment.net.xml`, `lust_segment_*.rou.xml` |

The run scripts (`run_lust_*.sh`) always use `mrsu_lust.sumo.cfg`. To run the 20.25 km2 segment, copy its config over the default one first:

```bash
cd ~/artery/scenarios/mrsu_lust
cp mrsu_lust.sumo.cfg mrsu_lust_roi15.sumo.cfg.keep      # keep the 15 km2 config
cp mrsu_lust_segment20.sumo.cfg mrsu_lust.sumo.cfg
./run_lust_segment_5runs.sh
```

Restore the 15 km2 config afterwards with `cp mrsu_lust_roi15.sumo.cfg.keep mrsu_lust.sumo.cfg`. The scripts `run_lust_roi15.sh` and `run_lust_k21_*.sh` belong to the 15 km2 variant.
